| 动态选课人数 / 选课竞争分析 | No | 不在当前业务范围内，且依赖外部教务数据 |

### 1.3 学业模块的弱提示边界（必须明确）

**一期仅允许做：**
- 成绩数据导入后的模块缺口展示
- 培养方案模块级风险提示
- “建议人工核验”的提醒
- 课程类型匹配级别的参考信息（前提是规则数据完整）

**一期明确不允许做：**
- 自动判定“能否毕业”
- 自动判定“学分已全部满足”
- 自动判定补修 / 缓修 / 免修是否完全成立
- 在规则不完整时给出强结论
- 基于非结构化、未经确认的数据直接生成选课建议

**前端必须显示的边界提示：**
> 本结果仅为辅助提示，不构成毕业资格、课程替代或教务最终结论；请以学院 / 学校正式审核结果为准。

## 2. 字段级权限矩阵（建议默认方案）

### 2.1 说明

- 本矩阵仅覆盖当前设计中最关键的角色：`学生`、`班主任`、`团委老师`。
- 其中：
  - `读` = 可查看
  - `写` = 可直接修改源数据
  - `审批写` = 只能写审批意见、备注、状态，不可改源数据
  - `范围` 默认指职责范围：学生=本人；班主任=本班 / 负责年级；团委老师=学院业务范围
- 对 `成绩`、`处分记录` 等权威字段，默认不允许上述角色直接改“源数据”，只允许通过导入或受控维护流程更新。

### 2.2 核心数据权限矩阵

| 数据项 | 学生 | 班主任 | 团委老师 | 默认说明 |
|--------|------|--------|----------|----------|
| 学号 / 姓名 / 年级 / 专业 / 班级 | 读：本人；写：No | 读：本班 / 本年级；写：No | 读：业务范围；写：No | 主数据默认由学院统一维护 |
| 联系方式 | 读：本人；写：建议仅提交变更申请 | 读：本班；写：No | 读：业务范围；写：No | 不建议老师直接改学生联系方式 |
| 成绩 / 学分情况 | 读：本人；写：No | 读：本班 / 本年级；写：No | 读：与奖助 / 预警 / 审核相关的业务范围；写：No | 权威成绩来源应来自导入或教务数据 |
| 培养方案缺口 / 学业风险提示 | 读：本人；写：No | 读：本班汇总或个体；写：No | 读：业务范围；写：No | 这是分析结果，不是权威源数据 |
| 政治面貌 | 读：本人；写：No | 读：本班；写：No | 读：业务范围；写：Yes | 默认由团委老师或受权党团老师维护 |
| 党团流程阶段 | 读：本人；写：No | 读：本班；写：No | 读：业务范围；写：Yes | 阶段推进与节点完成应由党团业务角色维护 |
| 处分记录 | 读：No（默认不展示） | 读：本班且按需；写：No | 读：业务范围且按需；写：No | 高敏感字段，不建议学生侧直接展示 |
| 奖惩 / 荣誉 / 实践记录 | 读：本人；写：No | 读：本班；写：No | 读：业务范围；写：建议仅受控维护 | 是否开放老师维护需甲方确认 |
| 请假 / 盖章 / 证明申请记录 | 读：本人；写：仅可提交 / 修改本人未完成申请 | 读：本班相关申请；写：审批写 | 读：业务范围申请；写：审批写 | 老师写的是审批意见和状态，不是改源主数据 |
| 申请附件 | 读：本人上传内容；写：本人在允许阶段内可替换 | 读：本班相关申请；写：审批写（备注） | 读：业务范围申请；写：审批写（备注） | 涉密附件需允许转线下 |
| 通知接收记录 | 读：本人 | 读：本班汇总 | 读：业务范围汇总 | 主要用于追踪触达效果 |
| 导出权限 | No | 仅导出本职责范围汇总；不导出高敏原始数据 | 仅导出业务范围汇总；高敏导出需额外授权 | 原始敏感数据导出应尽量收敛到管理员级别 |

### 2.3 默认决策建议

- `成绩`：三类角色均 **不直接写源数据**，只能通过标准导入更新。
- `政治面貌 / 党团流程阶段`：默认由 `团委老师` 写，`班主任` 只读。
- `处分记录`：默认不对学生开放；老师仅在“按需、按范围”场景下只读。
- `导出`：默认只允许汇总导出，不允许三类角色直接导出高敏明细。

## 3. 审批矩阵（建议默认方案）

## 5. 建议的甲方确认顺序

| 优先级 | 事项 | 原因 |
