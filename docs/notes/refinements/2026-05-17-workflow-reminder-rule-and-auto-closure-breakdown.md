# 党团提醒规则配置与自动闭环实施拆分

- 创建日期：2026-05-17
- 状态：`[x]`
- 关联主计划：`S23`
- 关联审计：`docs/notes/refinements/2026-05-17-web-requirements-summary-audit.md`

## 目标

把“完整的党团提醒规则配置和自动闭环”拆成可执行的前后端实施清单，作为后续正式开发的直接依据。

## 当前现状

- Web 端“节点提醒”页仍是占位态，只支持手动触发一次提醒生成，并在页面本地显示最近一次结果。
- 后端已有基础字段：`trigger_rule`、`due_rule_days`、`reminder_lead_days`。
- 后端已有提醒记录表 `WorkflowReminder`，并支持手动调用 `/admin/workflow/reminders/generate` 批量写入提醒记录。
- 当前缺口在于：没有规则查询接口、没有持久化运行记录、没有自动调度、没有提醒去重、没有“节点完成后自动取消未发送提醒”的闭环。

## 推荐首版范围

首版只闭环 `IN_APP` 站内提醒，不把短信、邮件、公众号接入同时纳入首轮范围。

首版完成标准：

- 管理端可以配置每个节点的提醒规则。
- 系统可以按规则自动生成并发送站内提醒。
- 节点逾期会自动转为 `OVERDUE`。
- 节点完成后，未完成发送的提醒会自动停止或取消。
- 管理端可以看到规则、待发送提醒、发送结果和最近运行记录。

## 前端要做什么

- [ ] `S23.1` 节点规则配置界面
  - 在流程模板的节点配置中展示并编辑 `trigger_rule`、`due_rule_days`、`reminder_lead_days`。
  - 为首版补齐 `reminder_enabled`、`repeat_interval_days`、`max_reminders`、`channel` 等新增规则字段的输入项。
  - 若后端支持逾期升级处理，再增加 `escalate_after_overdue_days` 或“转人工跟进”配置。

- [ ] `S23.2` 节点提醒页从占位态升级为真实工作台
  - 替换当前“提醒规则查询接口暂未接通”的提示。
  - 展示每个模板/节点当前生效的提醒规则摘要。
  - 支持按模板、节点、学生、提醒状态、日期筛选提醒记录。

- [ ] `S23.3` 手动执行与运行结果展示
  - 在提醒页保留“手动生成/立即执行”按钮。
  - 展示一次运行的 `created / sent / skipped / cancelled / failed` 统计，而不是只显示 `created`。
  - 展示最近若干次运行记录，而不是仅保留页面内存里的最后一次结果。

- [ ] `S23.4` 闭环可视化
  - 在学生流程列表和节点详情中展示节点状态变化：`PENDING / OVERDUE / DEFERRED / MANUAL_FOLLOW_UP / DONE`。
  - 在提醒列表里标明提醒是否已发送、已取消、因节点完成而关闭，减少老师误判。

## 后端要做什么

- [ ] `S23.5` 扩展数据模型与迁移
  - 在 `WorkflowNode` 上补齐首版所需规则字段，例如：
    - `reminder_enabled`
    - `channel`
    - `repeat_interval_days`
    - `max_reminders`
  - 为提醒运行过程新增持久化运行记录表，例如 `workflow_reminder_runs`，保存手动/自动执行的时间、渠道、统计结果、操作者、执行状态。
  - 必要时为 `WorkflowReminder` 增加 `run_id`、取消原因、失败原因等字段，便于追踪。

- [ ] `S23.6` 补齐规则查询与写入接口
  - 模板/节点查询接口返回完整提醒规则字段。
  - 模板保存接口支持写入新增提醒规则。
  - 提供提醒记录列表接口、最近运行记录接口、提醒概览接口，供 Web 真实展示。

- [ ] `S23.7` 提醒生成引擎
  - 在现有 `generate_reminders` 基础上补齐去重规则，避免同一节点同一天被重复生成。
  - 支持按 `reminder_lead_days` 和 `repeat_interval_days` 生成提醒。
  - 支持根据到期时间自动把节点从 `PENDING` 推进到 `OVERDUE`。
  - 当达到 `max_reminders` 后停止继续生成，必要时转 `MANUAL_FOLLOW_UP`。

- [ ] `S23.8` 提醒发送与闭环收口
  - 对 `IN_APP` 渠道接入 `create_system_in_app_notice_for_student`，真正把提醒发到学生站内消息。
  - 发送成功后把 `WorkflowReminder.status` 更新为 `SENT`，并写入 `sent_at`。
  - 当节点完成、流程完成或节点被人工改为无需继续跟进时，自动取消未发送提醒，标记为 `CANCELLED`。

- [ ] `S23.9` 自动调度器
  - 复用现有 `AuditArchiveScheduler` 的运行时调度模式，为党团提醒新增独立 scheduler。
  - 支持 `run_once`、周期执行、分布式锁/互斥锁，避免多实例重复跑任务。
  - 通过配置项控制是否启用、执行频率、默认渠道和是否自动发送。

- [ ] `S23.10` 回归测试
  - 规则保存/查询测试。
  - 提醒生成去重测试。
  - 节点完成后提醒取消测试。
  - 自动调度运行测试。
  - `IN_APP` 发送成功/失败状态更新测试。

## 推荐实施顺序

1. 先补数据模型、迁移和接口字段，保证规则可存可查。
2. 再把 Web“节点提醒”页从占位态改成真实工作台。
3. 接着完善提醒生成逻辑和去重、取消闭环。
4. 最后接入自动调度与站内提醒发送。

## 设计取舍

- 首版不建议同时接短信、邮件、公众号，否则会把“规则配置”和“消息通道治理”耦合在一起。
- 首版优先做“节点级规则 + 站内提醒 + 自动取消 + 运行记录”，这是最能体现闭环价值的一组能力。
