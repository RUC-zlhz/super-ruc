## FR-018: 学生画像聚合与全景视图

## Requirement

**ID:** FR-018  
**Title:** 学生画像聚合与全景视图  
**Priority:** Must Have  
**Status:** Draft

### Statement

系统应基于学籍核心字段（学号、姓名、专业、年级、班级、学籍状态）与动态成长字段（科研项目、学科竞赛、社会实践、志愿服务时长、学生干部任职等）聚合构建学生个人成长画像。基础学籍字段由教务同步/学院批量导入维护；扩展成长字段由辅导员、班主任或学生本人经审核后补录。画像仅作为信息聚合与展示工具，不得输出自动评分、综合排名或素质评价结论。辅导员/班主任/学院领导按权限范围查看；学生本人只能查看本人画像，并可对非结构化字段提交纠错申诉。

**账号与画像生命周期管理**：系统需感知学生学籍状态变化。当学生毕业、休学或转出信息学院时，其系统账号自动降级为"历史归档"状态；冻结其修改、申诉与补录权限；对应画像数据移出当前的班级/学院日常管理统计视图，仅保留超级管理员或授权辅导员的历史查阅权限。

## Traceability

| Traces To | ID | Description |
|-----------|-----|-------------|
| Customer Need | CN-015 | 学院需要聚合学籍与成长数据形成可共享的学生画像供管理侧参考 |
| Customer Problem | CP-012 | 学生成长数据分散于多个线下表格，辅导员/领导难以快速获得全貌 |

## Acceptance Criteria

- 辅导员按所辖范围可检索并查看学生画像；越权查看被拒绝并记录日志。
- 画像详情聚合学籍静态字段与动态成长字段；每条成长事实标注数据来源、录入人与最后更新时间。
- 敏感字段（标记 `is_sensitive=True` 或学籍敏感字段）默认脱敏；需申请查看完整信息时触发审批留痕。
- 学生本人只能查看本人画像，且不展示管理元数据（录入人、来源系统、审批人等）。
- 学生可对非结构化描述字段提交纠错申诉；辅导员可批准/驳回并决定是否回写到画像事实。
- 模块不输出自动评分、综合素质排名或毕业/晋升结论。
- 学籍状态（在读/休学/毕业/转出）作为全局拦截器的一部分：非在校状态账号自动切断业务提交流程，仅保留只读查询能力；日常统计视图默认只计入在读学生。

## Notes

- 学籍主数据复用 `students` 主表；动态成长字段在 `profile_facts` 表维护，跨模块事实复用通过 `source_ref` 记录来源。
- 纠错申诉复用审批思路：`profile_corrections` 维护申诉单，状态 `PENDING / APPROVED / REJECTED`。
- 所有读/写操作写入审计日志（event_type=`PROFILE`）。
